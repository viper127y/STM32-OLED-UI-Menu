 [1] 为什么 y 坐标写成 2.5 * emOLedFontSize_8x16 ?
----------------------------------------------------------------
 £★ 说明:
 核心原因: 字体枚举的枚举值 = 字符的像素高度 (不是随便定的)。
 例: emOLedFontSize_8x16 = 16 -> 高 16 像素, 宽 16 / 2 = 8 像素。
 所以 y = 2.5 * emOLedFontSize_8x16 就是 y = 2.5 * 16 = 40 像素,
 含义是 "按钮放在第 2.5 行文字的位置"。
 这样写而不是直接写 .y = 40 的好处:
 1. 可读性: 一眼看出在第几行, 而不是一个光秃秃的数字;
 2. 自适应: 以后字体换成 emOLedFontSize_12x24 (= 24) 时,
    y 自动变成 60, 布局比例不会乱; 写死 40 就得手动重算。
 总结: 用 "几行字" 代替 "几个像素" 描述位置, 坐标跟着字体走。

 [2] 字符串居中: sizeof 要减 1 + 正确的居中公式
----------------------------------------------------------------
 £★ 说明:
 (1) 为什么要 sizeof(...) - 1 ?
 C 语言字符串末尾藏着一个看不见的 '\0' (结束符), 编译器自动补上。
 例: static uint8_t s_aucLed0[] = "Led 0";
 内存实际是: 'L' 'e' 'd' ' ' '0' '\0' -> 共 6 字节。
 sizeof(s_aucLed0) = 6 (量的是整块内存, 含 '\0');
 减 1 之后 = 5, 才是真正要显示的字符个数。
 '\0' 只给库函数当 "到头了" 的记号 (如 strlen 内部数到它为止)。
 记住场景: sizeof 量整块内存 (含 '\0'), 算显示长度就减 1。

 (2) 常见写错: sizeof(s_aucLed0[0] - 1) 是错的!
 这里是 "元素值减 1", 运算结果提升成 int, sizeof(int) = 4,
 于是 6 / 4 = 1, 再除 2 乘字号再除 2 -> x = 0, 文字贴左。
 要减的是整体大小, 不是单个元素。

 (3) 居中公式直觉:
 居中 = 屏幕中心 - 文本一半宽度
 x = 128 / 2 - (sizeof(s_aucLed0) - 1) * (emOLedFontSize_6x12 / 2) / 2
 例: "Led 0" 5 个字符, 字符宽 = 字高 / 2 = 6,
 x = 64 - 5 * 6 / 2 = 49, 正好居中。
 注意: 公式里的字号要和结构体里实际用的字号保持一致。

 [3] 无符号数回绕 + 一条上边界同时防住上溢和下溢
----------------------------------------------------------------
 £★ 说明:
 (1) 数组元素个数的正确算法 (注意括号位置!):
     个数 = sizeof(s_apstButton) / sizeof(s_apstButton[0])
     sizeof(数组) = 3 * 4 = 12 (整体字节数), sizeof(元素) = 4,
     12 / 4 = 3 个元素, 最大合法下标 = 个数 - 1 = 2。
     写错姿势: sizeof(s_apstButton) / (sizeof(s_apstButton[0]) - 1)
     括号把 - 1 括进了分母, 变成 12 / 3 = 4, 边界值直接算错。

 (2) uint8_t 下溢回绕: 里程表直觉
     uint8_t 范围 0 ~ 255, 没有负数。
     ucSelectIndex--; 当它已经是 0 时, 0 - 1 不是 -1, 而是回绕成 255,
     像里程表倒着转一格, 直接翻到最大值。

 (3) 一条上边界 "一把抓":
     合法值只有 0, 1, 2; 非法值只有两种来源:
     上溢: 2 + 1 = 3; 下溢: 0 - 1 = 255。
     妙处: 两个非法值 (3 和 255) 都 >= 3, 合法值 (0~2) 都 < 3,
     所以一个 if 就全拦住:
       if (ucSelectIndex >= 3) { ucSelectIndex = 2; }
     前提: 变量必须是无符号数!
     若是 int8_t, 下溢得到 -1, -1 < 3 抓不住, 要判两头:
       if (ucSelectIndex < 0 || ucSelectIndex >= 3)
     记住场景: 无符号数 + 只判一条上边界 = 下溢和上溢一起防。

 (4) Ui_Task.c vPhyButtonExecuteAll 里的实际 bug (待修):
     1. if 条件括号括错 -> 边界算成 4, 保护圈破洞;
     2. 越界时把 4 赋给了 emButtonSelectStatus, 该改的是 ucSelectIndex;
     3. s_apstButton[255] 越界取到野指针, 解引用可能 HardFault;
     4. ucSelectIndex 是局部变量没初始化, 要改成
        static uint8_t ucSelectIndex = 0;
     5. DOWN 键处理块复制了两遍, 且 DOWN 越界应拉回 0 (循环菜单)。
